Guidelines

How to use it

The design system behind sbmadhav.com: professional enough for recruiters, fun enough for kids. Every new page should feel like part of the same site, in both color schemes, in both grown-up and kid mode.

Start a new page

  1. Copy template.html to the new page's folder (for example /projects/index.html). Keep <body class="md-page md-root">: both are required. md-page carries the --page ground, the heading faces and weights and the base type; md-root carries the font and colour, the 3px focus ring and the base link style. Add md-fill on a short page so its footer sits at the bottom of the viewport instead of mid-screen.
  2. Keep its <head> as is: the theme script, the font preloads, then the pinned /design-system/v/<version>/tokens.css and components.css, in that order. Never add a Google Fonts link or @font-face rules; tokens.css already declares the self-hosted faces.
  3. Keep the shared header between <!-- md-header --> and <!-- /md-header -->. Put the page's own parts in its slots (brand, nav, music, end) and run python3 compose.py header.html page.html with the pinned header.html (see Header below). Load the pinned header.js with defer.
  4. Write every piece of copy twice: <span class="pro">…</span><span class="kid">…</span>.
  5. Build from the components below; add page-specific styles with tokens only (var(--coral), var(--space-6), var(--radius-lg), font: var(--text-title)), never raw hex or raw font sizes.
  6. Add the page to the Explore menu: one entry in PAGES at the top of /assets/explore.js in the sbmadhav.github.io repo (path, icon, grown-up and kid title and one-line description).
  7. Check both schemes (sun/moon button), kid mode, a 390px-wide phone, and reduced motion before publishing.

Versions

Every release is published twice: at /design-system/<file> (the latest, which changes with every release) and at /design-system/v/<version>/<file>, which never changes once published. The current version is 2.2.0; versions.json lists every version.

  • Pin a version in every page: /design-system/v/2.2.0/tokens.css, components.css, header.html, header.js. A design-system release then changes nothing on a page until that page moves to the new version on purpose, in its own change, and each site can roll back alone.
  • Pinned files per version: tokens.css, tokens.json, components.css, header.html, music.html, header.js and compose.py.
  • Version numbers follow semver: a new token, class or component is a minor version; a fix that changes nothing a page relies on is a patch; renaming or removing a token or class is a major version. Existing token names and classes keep working within a major version.
  • The unversioned paths stay published for older pages, and the main site's worker precaches them. New pages should not use them.

The decision and its alternatives are in docs/adr/0001-versioned-releases-and-shared-header.md in the repo.

This repo

The design system lives in its own repo, sbmadhav/design-system, and GitHub Pages publishes it as a project site. Under the user site's custom domain that is sbmadhav.com/design-system/, the same URLs every page already links. _config.yml keeps README.md, CLAUDE.md and build.py out of the published site; tokens.json is published so other repos can read it.

  • Build. pip install markdown, then python3 build.py. Commit the generated files (tokens.css, index.html, template.html, v/<version>/, versions.json) with the change that produced them.
  • Release. Any change to a published file needs a new version in tokens.json (semver, see Versions). build.py writes v/<version>/; CI fails if a version already on main would gain, lose or change a file (python3 build.py --check-immutable origin/main). Unit tests for that check, for compose.py and for the rules components.css must keep (the focus ring's shape, tokens for every padding and control height, the 2.2 classes) live in tests/: python3 -m unittest discover -s tests.
  • Checks. build.py fails if an accent fill or -strong shade misses its contrast floor or a category colour misses AA in either scheme, if a token is missing from a scheme block of tokens.css, or if a hand-written file uses a raw colour. A pre-commit hook in .githooks/ and the workflow in .github/workflows/build.yml both run it and fail if it changed a file. Enable the hook once per clone: git config core.hooksPath .githooks.
  • Shared files from the site. Fonts (/assets/fonts/), the profile photo, the app icon, the Explore menu (/assets/explore.js) and analytics (/assets/analytics.js) are served by the sbmadhav.github.io repo. Keep those paths there.
  • Preview locally. Absolute /assets/ and /design-system/ paths need the whole site. Run node e2e/local-server.mjs and open http://127.0.0.1:8123/design-system/: it serves this checkout and takes everything else from the live site. The end-to-end tests run against it with BASE_URL=http://127.0.0.1:8123.
  • The site's color check. The home page inlines its colors for a fast first paint. sbmadhav.github.io keeps a pinned copy of tokens.json and compares against it; after changing a color here, refresh that copy there with python3 scripts/check-tokens.py --refresh.

The interactive version of this system, with live previews of every component, is kept privately in Claude.

Principles

  • Two audiences, one page. Every piece of copy has a grown-up version and a kid version. The layout never changes between them; only the words do.
  • Two schemes, two personalities. Daybreak (light) is a clean, cool slate-white page. Deep Space (dark) is a calm slate night sky. They should surprise people with how different they feel, while every component stays in the same place.
  • Friendly, never childish. Rounded shapes, chunky borders and a solid "ledge" under controls make things feel touchable. Restraint in copy and layout keeps it professional.
  • Play is opt-in. Music, motion and games never start on their own. Everything respects reduced-motion settings.
  • Show, then tell. Prefer an interactive demo (Brain Lab, Design Lab) over a paragraph that explains an idea.

Content fundamentals

  • Voice: first person, warm, plain words, dry humor in grown-up mode ("Zero-defect release. Principal engineer energy."), wonder in kid mode ("Whoa! We just blasted into deep space!").
  • Never use em dashes. Use a period, comma or colon instead.
  • Short. Ledes are one or two sentences. Card descriptions fit in two lines.
  • Grown-up copy names real things: titles, metrics, technologies. Kid copy names what it does: "builds robot helpers for a really big bank."
  • Sentence case for headings and buttons. Uppercase only for kickers (kicker style).
  • Numbers in stats are big and specific: 17, 2 → 25, +25%, $70M+.

The palette is called Harbor: three hues. Coral leads, deep teal supports, and amber (sun) is only for highlights. sky shares teal's values and plum shares coral's; they keep their own names so a page can still say what a color means (thinking, play) and the five tag and fill classes keep working. Because they look the same, never use sky and teal (or plum and coral) to tell two things apart: use the category colours.

Category colours

Six distinct hues for anything that must be told apart at a glance: belts, categories, balloon or tile colours in games, legend keys. They are the one place a page may show more than three hues.

  • Fill (cat-red to cat-purple): belts, tiles, chips, legend swatches. Always with on-accent text, and with a 2px edge border when the fill is the only boundary.
  • Strong (cat-*-strong): text, icons, chart lines and marks on bg, bg-alt or card.
  • Belts: white and black stay as the page's own fixed colours; yellow, orange, green, blue and purple use cat-yellow, cat-orange, cat-green, cat-blue and cat-purple.
  • Always pair colour with a word or shape (a belt name, a legend label). Colour alone never carries meaning.

Measured contrast (Daybreak / Deep Space). build.py and the end-to-end tests fail if any falls under 4.5, or if two of the six get too alike (CIE76 distance under 20).

How the colors stay accessible

The system follows the approach Stripe describes in Designing accessible color systems: every hue gets the same few lightness levels, so any color at a given level has the same contrast as every other hue at that level. Pick a level by job, not by hue, and contrast takes care of itself.

Level Tokens Job Rule
Fill coral, teal, sun, sky, plum Buttons, tags, chips, highlights, tile backgrounds Always carries on-accent text (at least 6.2:1). Never text on bg.
Strong *-strong Text, links, icons, chart marks, status labels At least 4.5:1 on bg, bg-alt and card.
Soft color-mix(in srgb, var(--x) 14%, var(--card)) Tinted panels, badges, icon tiles Text on it is ink or the matching *-strong.

State rules - Hover: buttons lift (transform and a deeper ledge); colors stay the same. Chips fill with sun and switch text to on-accent. Links keep their color and gain an underline. - Pressed or selected: fill with ink, text flips to bg (16.0:1 / 16.0:1). - Focus: 3px focus outline with a 3px offset, on every interactive element, following the element's own shape. - Disabled: 45% opacity. Disabled controls are exempt from contrast rules, but never rely on disabled styling alone to explain why something is unavailable.

Accent rules - Fills carry on-accent text; text, icons and chart marks use *-strong. White text on any fill fails and is not allowed. - Deep Space is calm by default: accents are soft coral and aqua, not neon glows or gradients. - Three hues in one composition. Coral leads, teal supports, amber only highlights. - Section tags take one accent each: sun for About, sky for Brain Lab, coral for Bug Hunt, plum for games, teal for Journey. - line is decorative. A control's boundary must come from edge (or a fill with at least 3:1 against its ground).

Typography

Four families, self-hosted as WOFF2 in /assets/fonts/ so pages make no third-party font requests. tokens.css declares every @font-face (generated by build.py), so linking it is enough. Do not repeat the @font-face rules in a page. Preload the two faces that render first:

  • JetBrains Mono for agent thoughts, code, costs and disclaimers.

  • Highlight one word in a hero heading with md-hl: a sun band behind the lower half of the word, the same in both schemes. Use it once per page.

Type tokens

Every style in the scale is a set of tokens, so a page never writes its own font size, and a change here reaches every page:

Token What it holds
--text-<style> The whole font shorthand: weight, size, line height and family. Use font: var(--text-title);
--text-<style>-size, -weight, -leading, -tracking Each part on its own, for when only one changes (font-size: var(--text-small-size)).
.md-text-<style> A class that sets the font and the tracking (and uppercase for kicker).

Styles: display-xl (hero name), display-l (page titles below the hero size, new in 2.1), heading (section titles), stat, title, card-title, cta (the label of the one big call to action, md-btn--lg: 22px, weight 800, new in 2.2), lede, body, small, nav (header links and app tabs), label, label-sm (compact controls), kicker, code. Aliases by role: --text-display is display-xl, --text-h1 is display-l, --text-h2 is heading, --text-h3 is title, --text-h4 is card-title.

display-xl, display-l, heading and cta are fluid (clamp()), so they shrink on phones without a media query. Set letter-spacing from the matching -tracking token: the font shorthand does not include it. Kickers also need text-transform: uppercase (the md-kicker and md-text-kicker classes do both).

Layout and spacing

  • Content max width content-max (1120px), gutter space-6 (24px), space-4 (16px) on phones.
  • Every section: space-section (72px) top and bottom padding; alternate plain sections with bg-alt bands that have a 1px line top and bottom.
  • Section header: a tag, a heading, then a lede in ink-muted at most 40em wide, then space-7 (28px) before content.
  • Cards in grids: 4 across on desktop, 2 under 980px, 1 under 560px.
  • No horizontal scroll at 390px (or 320px). The shared header hides its section links under 1180px and keeps Explore, the scheme button, music and the end controls.

Sizes: header-height (66px), control-height (40px: buttons, round icon buttons, Explore, the theme button), control-height-sm (36px, the same controls on phones) and, new in 2.2, control-height-lg (56px, the one big call to action, md-btn--lg), touch-target (44px, the least a tappable button is on phones), popover-max (380px, the widest a header panel or coach mark gets) and measure-prose (40em, the longest line of reading text; md-lede and md-prose use it).

Shape and depth

  • Radius ladder: radius-2xs 4, radius-xs 8, radius-sm 12, radius-md 16, radius-bubble 18 (speech bubbles), radius-lg 22, radius-xl 28, radius-pill, and radius-round (50%, circles).
  • Raised controls (buttons, chips, tiles, palette blocks, game boards) get a 2px edge border and a solid shadow-ledge. They lift on hover (translateY(-2px) with shadow-ledge-hover) and press down on click (translateY(2px) with shadow-ledge-press).
  • Cards and panels get a 1px line border, shadow-card, and lift 4px with a tiny tilt (-0.4deg) on hover.
  • Anything floating above the page (dialogs, sheets, toasts, popovers) gets shadow-modal. A soft amber ring around the current or selected item is shadow-glow.
  • Deep Space adds backdrop-filter: blur(8px) (--glass) to cards and controls so the starfield shows through softly.

Layers

Use the z-index tokens, never a number: z-base (1, content above the space backdrop), z-header (50), z-popover (60, panels that open from the header), z-overlay (100, sheets that are not a <dialog>), z-toast (120) and z-skip (400, the skip link). A <dialog> opened with showModal() sits in the top layer and needs none.

Motion

  • Gentle and looping: Bolt bobs (3.4s), planets drift (45 to 130s per crossing), stars twinkle, the hero blob morphs (12s).
  • Springy UI: toggles, the theme button and level nodes use --ease-spring (cubic-bezier(.5,1.6,.5,1)).
  • Durations: --duration-fast (.12s, press and lift), --duration-medium (.25s, switches and fades), --duration-slow (.4s, the theme button, dialogs and toasts entering). Things entering use --ease-out.
  • Sections fade up 18px on first scroll into view.
  • prefers-reduced-motion: reduce turns all of it off. Nothing essential may depend on motion.
  • Pause motion in the Explore menu does the same on every page (WCAG 2.2.2). It sets class="motion-paused" on <html> and remembers it; components.css stops CSS animation under it. Give every page-level reduced-motion rule an html.motion-paused twin, and have scripts that animate decoration check window.siteMotion.paused() and listen for the sitemotion event on document.

Interaction patterns

  • Kid mode: write both versions side by side as <span class="pro">…</span><span class="kid">…</span>; body.kidmode swaps them. Remember the choice; ?kid in the URL starts in kid mode.
  • Color modes: Daybreak (light) and Deep Space (dark). Pages follow the visitor's system setting by default. The round sun/moon button in the header (md-theme, run by header.js) is the one theme control on every page: a click switches scheme; a choice that differs from the system is saved in localStorage theme (light or dark), and switching back to match the system clears it. Set data-theme from a tiny inline script in <head> to avoid a flash. Pin any block to one mode with class="mode-daybreak" or class="mode-deep-space". There is no System / Daybreak / Deep Space picker any more.
  • Explore menu: every page has an Explore button (Star map in kid mode) that opens a panel listing every page as a card, jump links to the home page's sections, and LinkedIn, GitHub and Install app. It slides in from the right on desktop and up from the bottom on phones. The page list lives in one place, /assets/explore.js.
  • Bolt (the robot mascot) reacts to actions in a speech bubble under him. A tap-hint pill and a halo show until the first click.
  • Music is generated in the browser, never auto-plays, and pauses when the tab is hidden. Every site uses the same Music pill in its header; each brings its own tracks and panel. Games may take over the music while they run and give it back after.

Iconography

  • Inline SVG <symbol> sprites on a 32×32 grid, 2.4px round-capped strokes, no fills except small solid details; stroke uses currentColor in code.
  • Shown on icon tiles: a 54px radius-md tile filled with the accent at 18% and the icon in the full accent.
  • Illustrations (planets, rockets, astronaut, Bolt) use flat fills with a 3 to 5px navy outline.
  • No emoji in the UI. No brand logos of other companies.

Accessibility

  • Text meets 4.5:1 in both schemes: ink and ink-muted on bg, bg-alt and card.
  • Focus: outline: 3px solid var(--focus); outline-offset: 3px, following the element's own shape: a pill's ring is a pill, a card's ring keeps its corners. A target scripts move focus to with tabindex="-1" (main after the skip link, a section or a heading after a view swap) shows no ring, since Tab never reaches it; a page that wants one adds its own rule. Only those landmarks and headings lose the ring: an interactive element with tabindex="-1" (a roving-tabindex tab, tile or key reached with the arrow keys) keeps it.
  • Toggles use role="switch" and aria-checked; chips and toggle buttons use aria-pressed; live results use aria-live="polite".
  • Every game and animation has a still, keyboard-usable path.
  • Pages with repeated navigation start with <a class="md-skip" href="#main">Skip to content</a> and a <main id="main" tabindex="-1">.
  • Anything that scrolls sideways (code samples, wide tables) is focusable and named: tabindex="0" role="region" aria-label="…". For tables that box is md-table.
  • Buttons are at least touch-target (44px) tall on phones (600px and narrower); only md-btn--sm, for tools and games, stays 32px.
  • At 320px wide nothing scrolls sideways: header controls wrap to a second row, and a control whose label is hidden on phones keeps an aria-label.
  • Text that is only for screen readers uses md-sr-only. Toasts are announced from a role="status" stack and never block taps.

Components

Button

Classes: md-btn, md-btn--primary, md-btn--sm, md-btn--lg.

A pill with a 2px edge and a solid ledge underneath that lifts on hover and presses down on click.

  • Primary (md-btn md-btn--primary): one per view, the main call to action. Coral in both modes. Label in on-accent.
  • Secondary (md-btn): card background. Use for every other action.
  • Small (md-btn--sm): inside tools and games (Undo, Clear, Reset).
  • Large (md-btn--lg): the one big call to action on a landing or a start screen, 56px tall (control-height-lg) with the cta label style. One per page, and it is the primary.
  • Heights sit on the control scale: 40px (control-height) by default, 32px small, 56px large. On phones (600px and narrower) every button but the small one is at least touch-target (44px) tall.
  • Labels are verbs in sentence case and can have kid and grown-up versions ("See how my agents think" / "Peek inside a robot brain").
  • Icons go before the label at 18px (1.1em in the large size, where an arrow may follow the label).
  • The consumer provides the label, the click handler and disabled when the action is not available.

Actions

Classes: md-actions, md-actions--stack.

The row of buttons under a heading or at the end of a card: <div class="md-actions"><button class="md-btn md-btn--primary">Start</button><button class="md-btn">Not now</button></div>.

  • Buttons wrap with space-3 gaps; the row gets space-5 above and below.
  • md-actions--stack stacks them full width under 560px, in markup order. Put the primary first in the markup when it should come first: there is no CSS reordering, so focus order and visual order stay the same (WCAG 2.4.3).

Chip

Classes: md-chip with aria-pressed.

A pill-shaped choice for picking one option from a small set: Brain Lab questions, Design Lab scenarios.

  • Use aria-pressed="true" on the selected chip; it fills with ink and its text flips to bg.
  • Hover fills with sun and on-accent text.
  • Keep labels under about 30 characters; they wrap as a row with space-2 gaps.

Tag

Classes: md-tag, md-tag--sky|coral|plum|teal.

The small colored label that opens every section, above the heading.

  • One accent per section: sun (default), sky, coral, plum, teal. Pick by meaning: play is plum, debugging is coral, thinking is sky, career is teal.
  • Text is on-accent in the display face at 14px. It can have kid and grown-up versions ("Design Lab" / "Robot Maze").
  • One tag per section; never inline in body text.

Card

Classes: md-card, md-icon-tile.

The default container: white (Daybreak) or dark slate (Deep Space), 1px line border, radius-lg, shadow-card, space-5 padding.

  • Optional icon tile on top: 54px, radius-md, filled with the card's accent at 18% (color-mix(in srgb, var(--teal) 18%, transparent)) with the icon in the matching *-strong color.
  • Heading in card-title; description in small, ink-muted, two lines or fewer.
  • Lifts 4px and tilts -0.4deg on hover. Use in grids of 2 to 4.

Stat

Classes: md-stat with md-kicker, md-value, p.

A metric tile: kicker label, a big number in the stat style, and an optional one-line note.

  • Numbers are specific and short (17, 2 → 25, $70M+). Put the unit in the number, not the label.
  • Use 2 to 4 in a row. Scoreboards in games use the same tile.
  • The note is ink-muted at 14px; give kid mode its own wording.

Switch

Classes: md-switch with md-track and md-knob, role="switch".

The on/off pill used for kid mode, with a springy knob.

  • role="switch" and aria-checked carry the state; the track fills with sun when on.
  • The label names the mode, not the action. Shorten it on phones ("Kid mode").
  • Turning kid mode on swaps every .pro span for its .kid twin and gets a confetti burst.

Bubble

Classes: md-bubble.

Bolt's speech bubble: card background, 2px edge, 18px corners, ledge shadow and a pointer toward the speaker.

  • Place it under Bolt with the pointer up, never over content or photos.
  • One or two short sentences, in the current mode's voice. Auto-hide after about 4 seconds.
  • Announce it with role="status" and aria-live="polite".

Header

Files: header.html (markup), components.css (md-header and friends), header.js (the theme button).

The sticky bar at the top of every page on sbmadhav.com, the same everywhere: Bolt's head and the name (a link home), the page's own nav, the Explore button, the sun/moon theme button, the Music pill and the page's end controls. 66px tall, bg at 88% with a blur, a 1px line under it.

<!-- md-header -->
<!-- slot:nav --><nav class="md-nav" aria-label="Sections"><a href="#work">About</a><a href="#lab">Brain Lab</a></nav><!-- /slot:nav -->
<!-- slot:end --><button class="md-switch" id="kidBtn" role="switch" aria-checked="false" aria-label="Kid mode">…</button><!-- /slot:end -->
<!-- /md-header -->
  • Compose it at build time, never by hand (a malformed, duplicated or unclosed slot marker is an error, so page content is never dropped): python3 compose.py header.html page.html (with the pinned header.html) fills the block from the partial and keeps the page's slots. Run it again after moving to a new version; --check fails when a page's header differs from the partial, for CI.
  • Slots: brand (the name next to the logo, default "Madhav"), nav, music (the Music pill) and end (a kid mode switch, a Player chip). Everything outside the slots is fixed.
  • Nav: <nav class="md-nav"> with plain links; mark the current one aria-current="page" (or "true" for app routes) and it fills with ink. Section links hide under 1180px (the Explore menu lists them). For app tabs that must always show, add md-header--tabs to <header>: under 1180px the tabs move to their own rows and wrap.
  • Phones: under 600px the controls shrink to 36px and Explore and Music show their icon only; under 420px the end controls wrap to a second row; under 360px the name hides and the logo keeps the link's name. In a tabs header the brand pushes Explore, the theme button and the end controls together to the right end of the first row at every width, and the tabs take their own rows.
  • No Shadow DOM: the header is plain markup, so kid mode, Pause motion and the fonts work in it like anywhere else.

Theme button

Classes: md-icon-btn md-theme (in the header).

The round sun (Daybreak) or moon (Deep Space) button. header.js handles the click, the saved choice, theme-color, and the button's name ("Switch to Deep Space (dark) scheme"). Pages can listen for the sitetheme event on document (to have Bolt say something), and set data-track="<area>" on the button to record the switch with siteTrack.

Music pill

Markup: music.html. Classes: md-music, md-music-btn, md-music-lbl, md-eq, md-music-next.

A pill with a note icon, the word "Music" and a three-bar equalizer, plus an optional next-track button. It never plays on its own.

  • Play and pause (the home page): the button has aria-pressed; "true" while playing fills the pill with ink and makes the equalizer dance.
  • Open a panel (Vedic Math): the button has aria-expanded and aria-controls; add the class is-on to .md-music while music plays.
  • On phones only the note shows; the button keeps its aria-label.

Raised tile

Classes: md-tile, md-tile-t, md-tile-s, md-tile--fill, md-tile--center.

A card-sized control with a button's edge, ledge, lift and press: grade and game pickers, mode cards, keypad keys, belts.

  • A <button> or <a>. Title in md-tile-t (card-title), an optional line in md-tile-s.
  • Selected: aria-pressed="true" (or aria-current) tints it with sun.
  • md-tile--fill fills it with --tile-fill (default sun) and switches text to on-accent: style="--tile-fill: var(--cat-blue)". A selected fill tile keeps its fill and shows an ink ring instead.

Text input

Classes: md-input (on <input>, <select> or <textarea>), md-label, md-hint.

  • Always with a visible md-label tied by for; put help in md-hint and link it with aria-describedby.
  • 2px edge border, radius-sm, 40px tall. aria-invalid="true" turns the border coral-strong; say what is wrong in words too.

Dialog

Classes: md-dialog on a <dialog> opened with showModal(), md-dialog-head, md-dialog-foot.

  • A scrim behind it, radius-xl, shadow-modal, solid card (never see-through). Name it with aria-labelledby pointing at its <h2>.
  • A round close button in the head (md-icon-btn md-icon-btn--sm, aria-label="Close"); Escape closes it too.

Popover

Classes: md-popover.

The solid floating surface for a panel opened from the header (the music panel, a settings panel) and for a coach mark. A card is glass in Deep Space and is for content; a popover is never see-through.

  • card over bg, 1px line, radius-xl (radius-lg on phones), shadow-modal, z-popover, space-4 padding, at most popover-max (380px) wide; on phones let it take the viewport minus the gutter.
  • The page positions it and gives it a max-height; it scrolls inside.
  • Name it: role="dialog" aria-labelledby="…" for a coach mark or a panel that takes focus, role="region" for one that does not. Close it on Escape and on a click outside.

Progress bar

Classes: md-progress, md-progress--sm (6px), md-progress--lg (16px).

  • <div class="md-progress" role="progressbar" aria-label="…" aria-valuemin="0" aria-valuemax="100" aria-valuenow="60"><span style="--value:60%"></span></div>, or a native <progress class="md-progress">.
  • The track is line, the fill teal-strong; change it with --bar (for example --bar: var(--sun-strong) for a timer).

Toast

Classes: md-toasts (the stack), md-toast.

  • One stack per page: <div class="md-toasts" role="status" aria-live="polite">. Append a md-toast, remove it after about 3 seconds (add is-leaving first to fade it).
  • The stack and the toasts have pointer-events: none, so a toast never blocks a tap on the page under it. A link or button inside a toast still works.

Round icon button

Classes: md-icon-btn, md-icon-btn--sm.

A 40px circle (32px small) with one 20px icon: close, flip back, play. Always give it an aria-label.

Link button

Classes: md-link.

A <button> that reads as a link, for small inline actions ("Reset play mode"). Underlined in coral, so it is told apart by more than colour. Bare links (an <a> with no class) on an md-root page share this look, ink and bold with the coral underline, so a link and a link button match; a page's own rule for its links still wins.

Prose

Classes: md-prose.

Long-form reading: privacy, terms, a guide, a parents page. Wrap the text in <div class="md-prose">.

  • Every child keeps to measure-prose (40em); tables (md-table), figures and code samples may run the full width.
  • Headings come from the type scale: h1 is --text-h1 (display-l), h2 is --text-h3 (title) with space-9 above and a scroll margin that clears the sticky header, h3 is --text-h4 (card-title). Headings on every md-page balance their lines (text-wrap: balance).
  • Paragraphs and lists get space-4 below and list items space-1-5 between; a rule (hr) gets space-7 around; a blockquote gets a 4px sun bar on a soft sun tint. Inline code is font-mono at 0.9em.

Table

Classes: md-table, md-table--stack.

A data table that may be wider than a phone: <div class="md-table" tabindex="0" role="region" aria-label="Belts, table"><table>…</table></div>. The box scrolls sideways, keyboard users can reach it, and a shadow on each edge shows only where there is more to scroll.

  • Cells have 1px line borders and space-2 by space-2-5 padding in the small style; header cells sit on bg-alt in bold.
  • md-table--stack turns each row into a block under 560px with the column heading before each cell: give every td a data-label="<column heading>". The thead stays in the accessibility tree.

Footer

Classes: md-foot.

The site footer: a line on top, space-7 of padding, muted small text and a row of bold links with no text separators between them.

<footer class="md-foot"><div class="md-wrap">
  <p>One line about the site.</p>
  <nav aria-label="Site"><ul><li><a href="/privacy/">Privacy</a></li><li><a href="/terms/">Terms</a></li></ul></nav>
</div></footer>
  • Links are ink, bold, at least control-height-sm (36px) tall, and underline in coral on hover.
  • On a short page add md-fill to <body> so the footer sits at the bottom of the viewport.

Highlight

Classes: md-hl.

One word in a display heading with a sun band behind its lower half: <h1>Speed tricks for <span class="md-hl">everyone</span></h1>. The same in both schemes. Once per page, and only in a display heading: over the band the text measures 11.2:1 in Daybreak and 3.4:1 in Deep Space, enough for large text, not for body text.

Segmented control

Classes: md-seg (or the older name md-modes) with <button aria-pressed>.

One choice from two to four: leaderboard periods, units. Not for the color scheme, which is the theme button.

Kicker and screen-reader-only text

Classes: md-kicker, md-sr-only.

  • md-kicker is the uppercase label (kicker style, ink-muted) and works anywhere, not only in a stat.
  • md-sr-only hides text visually but keeps it for screen readers.

Icons

The line icons from sbmadhav.com, exported from its inline SVG sprite. 32×32 grid, 2.4px round-capped strokes, drawn here in ink navy (#151B2B).

Bolt, the site's original robot mascot: teal body and arms, pale mint face, coral antenna and cheeks, amber chest, navy outlines.
